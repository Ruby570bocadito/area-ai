## Tarea 1 — Índice `Knowledge.campaignId` (propuesta bugs-11 pendiente 4)
- **Procedencia:** bugs-11 la propuso («BAJA — escala futura… propuesta para Pulimiento/producto con anuncio §2.5»); pulimiento-12 la excluyó explícitamente de su ronda («NO toco schema.prisma — material de la ronda siguiente»). Esta ronda es esa ronda siguiente.
- **Cambio:** `@@index([campaignId])` en el modelo `Knowledge` (`prisma/schema.prisma`, commit `19fc615`) — la ficha de campaña (`/historial/[id]`) y las consultas de conocimiento por campaña filtran por `campaignId`; hasta ahora solo existía `@@index([team])`, de modo que cada ficha escaneaba la tabla de lecciones completa.
- **Aplicación:** `bunx prisma db push` sobre la BD del entorno (13 ms, sin pérdida de datos; `prisma generate` regenerado con el cliente v6.19.2).
- **Verificación:**
  - `sqlite_master` lista `Knowledge_team_idx` + `Knowledge_campaignId_idx` (más el autoindex del id).
  - `EXPLAIN QUERY PLAN SELECT * FROM Knowledge WHERE campaignId = ?` → `SEARCH Knowledge USING INDEX Knowledge_campaignId_idx` (antes: `SCAN Knowledge`).
- **Complemento de la propuesta de bugs-11 — `Setting.value` con límite a nivel de esquema: NO aplicable en SQLite.** El dialecto SQLite mapea `String` de Prisma a `TEXT`, que no admite longitud máxima declarada; Prisma no ofrece `@db.VarChar` efectivo para SQLite (el atributo existe para otros dialectos y se ignora aquí). El tope real y eficaz es el **413 de la ruta** (bugs-11, Menor 1: `MAX_BASE_URL=2048`, `MAX_MODEL=200`, `MAX_API_KEY=4096`). Se documenta el porqué en lugar de fingir un límite de esquema inexistente.
